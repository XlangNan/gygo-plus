# gygo

> 光鸭云盘分享链接追更监控：**丢一个别人的分享链接进去，出新集自动转存到你的光鸭云盘。**

专门给还在更新中的电视剧/剧集用。添加监控后每小时自动去检查一次链接，
发现里面多了新文件（比如更新的几集），就只把新增部分转存到你指定的目录。
**已有的剧集不会重复转存。**

主流程只用 Python 标准库，零第三方依赖，镜像很小，飞牛 / 群晖 / 任意 Docker 设备都能跑。

---

## ⚠️ 先看这几条

1. **扫描间隔最低 60 分钟**，代码里写死下限，改不了。这是出于风控考虑——
   光鸭上线才几个月，风控策略不明，扫太勤容易把账号搞限流，得不偿失。
2. **接口是参照公开实现逆向整理的，不是官方文档**，光鸭随时可能调整。
   如果某天突然全部报错，大概率是接口变了，提 Issue 反馈。
3. **转存需要登录，查看分享不需要。** 所以即使登录态过期，监控照样能发现"出新集了"，
   只是转存那步会暂停，重新登录后自动补上。
4. **转存的目标目录会自动创建**，填 `影视/美剧/某某剧` 这种路径就行。
5. **v1.0.3 起已用真实账号跑通全链路**：短信登录 → 分享解析 → 递归列举 12 集 →
   差集检测 → 转存 → 文件落盘，全部实测通过（v1.0.2 及之前有个人盘根目录
   识别错误，会导致"转存报父目录不存在"，务必更新）。

## 一、Docker 部署（推荐）

### 路线 A：飞牛 FnOS 图形界面

1. 应用中心装好「Docker」。
2. 打开 Docker → **镜像仓库** → 搜索 `tianjian518/gygo` → 拉取。
3. 「容器」→「创建容器」→ 选刚拉取的镜像 → 端口映射：容器 `5099` → 主机 `5099`。
4. **挂载一个目录**：容器路径 `/data` → 主机随便一个文件夹（存监控配置和登录态，别漏）。
5. 浏览器打开 `http://飞牛IP:5099`。

### 路线 B：docker compose

```bash
docker compose up -d
```

默认端口 **5099**（刻意避开 casgen 的 5000 和 139cas 的 5244，不会打架）。

## 二、怎么用（全鼠标，四步）

1. **登录**：填手机号 → 点「发送验证码」→ 收到短信后填进去 → 点「登录」。
   登录态会持久化，重启容器不用重新登录（token 过期会自动用 refresh_token 续期）。

2. **添加监控**：把别人的光鸭分享链接整段粘进去。
   **提取码不用单独填**——只要文字里带 `提取码：xxxx`、`访问码：xxxx`、`?pwd=xxxx`，
   程序会自动识别。支持全角问号、已编码的链接、以及带 `#` 的前端路由链接。
   然后填「转存到我的目录」（留空=根目录），间隔保持 60 分钟即可。

3. **建基线**：点「添加」后会立刻拉一次链接，把**当前已有的文件记下来**。
   这一步不会转存任何东西——已经有的剧集不会重复搬一遍。
   界面上会显示「已添加，基线 N 个视频（这些不会被转存）」。

4. **之后就不用管了**：后台每小时自动扫一次，只转新增的集数。
   列表页能看到每项的：状态、上次扫描时间、最近一次结果。
   也可以随时点「立即扫描」手动触发。

## 二之二、几个实用功能

### 过滤规则（只转你想要的）

添加监控时点开「高级选项」：

| 项 | 作用 | 例子 |
|---|---|---|
| 只转含 | 文件名包含这些词才转，逗号分隔，支持 `*` | `S01, 2160p` |
| 排除含 | 命中就跳过 | `预告, 花絮, srt, 彩蛋` |
| 最小体积 | 小于这个 MB 数的不转 | `200`（滤掉小体积枪版） |

被过滤掉的文件也会记进基线，**不会每轮重复判断**。

### 保持子目录结构

默认开启。分享里是 `剧名/Season 01/S01E01.mp4`，转存后还是分季放好，不会所有季平铺在一起。
如果分享最外层那个目录名跟分享标题一样（很常见），会自动剥掉这一层，避免在
`影视/剧名/` 下面又套一个 `剧名/`。

### 单次转存上限 20 个

分享方一次性补更 50 集时，一轮只转 20 个，剩下的排队等下一轮，
不会一口气把账号当日额度打满、也不容易触发风控。

### 运行日志

网页底部「运行日志」直接看，同时写进容器的 `/data/gygo.log`（超 1MB 自动轮转）。

```bash
docker logs gygo          # 警告以上级别
docker exec gygo cat /data/gygo.log
```

### 重转全部

监控项上「重转全部」= 清空基线，下一轮把分享里所有文件当新出的重新转一遍。
适合转存失败想重试、或者换了个目标目录的情况。分批进行，不会一次灌满。

## 三、状态都是什么意思

| 状态 | 含义 | 要管吗 |
|---|---|---|
| **正常** | 上次扫描一切顺利 | 不用管 |
| **出错** | 网络抖动之类，下个周期自动重试 | 一般不用管 |
| **链接失效** | 分享被取消或过期，已停止扫描 | 需要换链接 |
| **已暂停** | 登录态失效，重新登录后自动恢复 | 重新登录 |

链接失效只影响那一项，**不影响其它监控**。

## 四、接口备忘（排错用）

分享侧（免登录）：

| 接口 | 用途 |
|---|---|
| `POST /nd.bizuserres.s/v1/get_share_summary` | 查分享是否有效 |
| `POST /nd.bizuserres.s/v1/get_share_access_token` | 提取码换分享 token |
| `POST /nd.bizuserres.s/v1/get_share_page_files_list` | 列举分享目录（**page 从 1 开始**） |

登录侧与业务侧：

| 接口 | 用途 |
|---|---|
| `POST account.guangyapan.com/v1/shield/captcha/init` | 短信登录第一步 |
| `POST account.guangyapan.com/v1/auth/verification` | 发短信 |
| `POST account.guangyapan.com/v1/auth/verification/verify` | 校验验证码 |
| `POST account.guangyapan.com/v1/auth/signin` | 拿 access_token |
| `POST account.guangyapan.com/v1/auth/token` | refresh_token 续期 |
| `POST /nd.bizuserres.s/v1/restore_share` | **转存**（需登录） |
| `POST /nd.bizuserres.s/v1/get_task_status` | 轮询转存任务 |
| `POST /nd.bizuserres.s/v1/file/get_file_list` | 列个人盘目录（**page 从 0 开始**） |
| `POST /nd.bizuserres.s/v1/file/create_dir` | 建目录，字段名是 `dirName` |
| `POST /nd.bizuserres.s/v1/file/delete_file` | 删除文件/目录（异步，返回 taskId） |

几个容易踩的坑，改代码时注意：

- **根目录一律是空字符串 `""`**（个人盘和分享都是）。传 `"0"` 接口**不报错**，
  只回 `data:{}` —— 表现是"列目录永远空、建目录报父目录不存在"，极难排查。
  代码里 `_norm_fid()` 已经把 `0`/`root`/`/` 全部归一化成 `""`。
- 分享接口分页 **从 1 开始**，个人盘接口 **从 0 开始**。
- `restore_share` 要**两个 token**：请求头是用户的 Bearer，请求体里是分享的 accessToken，别混。
- 转存接口只返回 `taskId`，不返回新文件 ID。
- 分享列表用 `resType=2` 表示目录；个人盘列表用 `dirType`/`resType`。

## 五、出问题了？先跑自检

接口是逆向整理的，官方一改就可能失效。**遇到问题第一件事是跑自检**，
它会告诉你到底是"接口变了"还是"你配错了"：

```bash
# 容器里
docker exec gygo python3 selftest.py "你的分享链接"

# 或者源码目录
python3 selftest.py "你的分享链接"
```

不用登录就能跑，依次检查：链接解析 → 分享是否有效 → 换 token →
**递归列举（最容易出问题的一步）** → 登录接口路径是否还活着。

输出里 `[!!]` 那几行就是问题所在，贴到 Issues 即可。

> 已知会踩的坑：光鸭分享接口用 `resType=2` 表示目录（不是 `fileType`）。
> 如果哪天递归列举返回 0 个文件，八成是官方又换了类型字段。

另外还有一套**纯逻辑自测**，不联网不登录，改完代码跑一下心里有底：

```bash
python3 tests/test_core.py
```

覆盖目录结构保持、过滤规则、单次转存限流、失败重试、基线推进、手机号规范化，共 39 项。

## 八、版本历史

- **v1.4.0**（当前）：**防重复转存 + 改名安全**。
  1. **重复链接防护（根因修复）**：`act_add_monitor` 添加前按 `share_id` 查重，同一链接已存在则直接返回已有项、不再新建、不再触发重复全量转存。实测遮天 2023 被建成 5 个监控项 → 盘里每集 5 个副本，根因就是这里没查重。
  2. **清理重复监控项 API** `POST /api/monitors/cleanup`：同 `share_id` 只留最早一个，删除其余（只删配置、不删盘文件），一键清掉历史遗留的多个重复项。
  3. **盘内同名副本去重 API** `POST /api/monitors/{id}/dedupe`：递归扫描目标目录，按「所在目录 + 文件名」分组，同组 > 1 个则删多余、每组留 1 份；默认 `dry_run` 只出报告，确认后传 `dry_run=0` 才真删，用于清掉盘里每集多份的副本。
  4. **改名安全（记住目录 fid）**：光鸭目录改名后 `fid` 不变，gygo 现在缓存目标目录与分享子目录的 `fid`，改名后新集数仍转进改名后的同一目录，不会再"按名字找不到就新建一个原名目录、把一部剧拆成两份"。要换位置请在 gygo 改监控项的「目标目录」，别在光鸭里改文件夹名。
  单测 81 项全过（新增 L 重复链接防护 / M 改名安全 / N 清理重复项 / O 盘内去重 四项回归）。
- **v1.3.1**：**修复分享列举分页 bug（遮天 2023 等"大文件夹"被重复列举成上万个副本、转存必失败）**。
  根因：光鸭 `get_share_page_files_list` 接口用的是**游标分页**（响应带 `cursor` + `hasMore`），
  会**忽略 `page` 参数**。原代码硬传 `page:1,2,3…` 翻页，光鸭始终返回第一页同样的 50 个文件，
  `len(items) < 50` 永远不成立 → 死循环翻到 `MAX_PAGE=200` → 列举出 10000 个重复文件（如遮天 2023
  实为 178 集，被列成 10000 个、10.6TB 注水副本），转存时直接撑爆配额。现改为**游标分页**
  （带 `cursor` 翻页，靠 `hasMore` 判断是否到尾），并**兼容**不带 `cursor/hasMore` 的旧式页码分页。
  修复后实测遮天 2023 正确列举 178 集、零重复。单测 65 项全过。
- **v1.3.0**：修复"首次转存只转 20 集、一两百集要分轮补好几个小时"的问题。
  此前 `MAX_PER_SCAN=20` 这把"限速锁"被同时用在了**追更**和**首次全量回填**上：
  只要不是走"添加即转存"那条全转路径（比如先未登录添加、或没勾"添加时立即转存"，
  登录后第一次真正的转存走的是扫描路径），就会被 20/轮 卡死，200 集要分 10 轮按小时补。
  现把两件事拆开：**追更（基线已有内容）仍限 20/轮**，慢慢补防风控；**首次全量回填
  （基线为空）不再限 20**，一次性把整部剧/整部动漫全部转存完。单测 59 项全过。
- **v1.2.2**：修复"文件夹里出现副本、20 集变 40 集"的重复转存问题。根因有二：
  (1) v1.2.0 的"添加即转存"是先**全量转存再建基线**，而 v1.2.1 的 `scan_now()` 会在
  添加后立刻后台扫描——扫描在"基线还是空"的窗口抢跑，把整批已转文件又当"新增"转一遍；
  (2) 手动"立即扫描" `act_scan` 没有纳入 `_busy` 互斥，会和定时扫描并发同一链接、
  都读旧基线、都判"新增"，同样翻倍。修复：添加即转存时**先建最小基线、转存期间占住
  `_busy`、成功一批增量写回基线**，扫描抢跑会被 `_busy` 挡掉、判为空差集不重复；同时
  `act_scan` 也纳入 `_busy` 互斥（占用时返回"稍候"）。单测 55 项全过。
- **v1.2.1**：修复"添加/登录后不立即扫描"的问题。v1.2.0 添加链接或登录后，
  监控项要等满一个扫描周期（默认 60 分钟）或被手动点扫描才工作，体验上像"没反应"。
  现新增 `scan_now()`：**添加链接后、登录成功后立刻在后台触发一次扫描**，不用干等。
  重复触发会被调度器去重，不会重叠扫描。单测 47 项全过。
- **v1.2.0**：**添加链接即转存已有视频**。此前添加监控只建基线、不转存已有
  文件（设计上为避免一次性灌爆），导致新用户添加链接后盘里空空、只能等下次更新。
  现默认在添加时把分享里**当前已有的视频也立刻转存**（分批限流，每批 20 个、批间降速），
  之后每次扫描只追"新出的"，即追剧逻辑。前端新增复选框「添加时立即转存已有视频」
  （默认勾选，取消则只追新）。未登录也能添加链接（先攒着，登录后首次扫描自动转存全部）；
  全局未登录时调度器跳过扫描，避免反复刷错误日志。单测 44 项全过。
- **v1.1.2**：修复目录结构保持时**错误剥掉外层文件夹**的 bug。原先逻辑发现
  分享顶层文件夹名与分享名一致就剥掉那一层，导致「同名文件夹包视频」这类分享
  只转出了视频、丢了外层文件夹。现改为**完整保留分享内的相对目录结构**，原样
  镜像到目标目录下。新增客户端 `move_files()`（整理用，接口 `/file/move_file`）。
- **v1.1.1**：修复短信登录 `captcha_invalid` 报错。根因是光鸭服务端把
  captcha 里的手机号格式化为 `+86...`，而登录时若传入不带 `+86` 的纯数字就会对不上。
  现已在客户端入口统一 `normalize_phone()`，用户输 `18155958936` / `86181...` /
  `+86 181 ...` 都能正常登录。
- **v1.1.0**：保持分享内子目录结构（多季剧不再全平铺）、单次转存上限 20 个防风控、
  转存任务状态校验、过滤规则（关键词/最小体积）、运行日志、监控项编辑与重置基线、
  目录浏览、健康检查接口。
- **v1.0.3**：修复个人盘根目录识别错误（根是空字符串不是 `"0"`），真实账号端到端跑通。
- **v1.0.2**：新增 `selftest.py` 自检工具。
- **v1.0.1**：修复分享递归列举（光鸭用 `resType=2` 表目录）。
- **v1.0.0**：初始版本。
